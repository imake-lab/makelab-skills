# SVG 绘图规范

本技能产出的所有图都是 SVG 文件：应用架构图、技术架构图、模块依赖图、ER 图、时序图、改造链路与流程图、边界图、运行链路图。目标是打开就清楚、放大不糊、可以直接编辑，在 GitHub 上也能正常显示。

## 1. 放在哪、叫什么

所有图都放在 `make-skill-legacy-takeover-output/diagrams/`，**只画下面这几张**，不另外加图。

| 图 | 文件 | 内容 |
| --- | --- | --- |
| 应用架构图 | `app-architecture.svg` | 顶部使用者；中间按业务域分组的模块，每个写一句话业务能力；底部共用的平台能力；域之间画主要业务流向。不画技术栈 |
| 技术架构图 | `architecture.svg` | 前端、后端、数据库、中间件分层；底部一排画外部依赖，关键依赖、中间件、外部 API 三类用不同深浅的橙色 |
| 模块依赖图 | `module-deps.svg` | 只画项目自己的模块，按层分组，箭头从使用方指向被依赖方；循环依赖的连线标红 |
| ER 图 | `data-model-er.svg` | 核心表和关系，逻辑关联用虚线 |
| 核心接口时序图 | `sequence-<名>.svg` | 一个核心写接口从入口到 DB 的调用链 |
| 改造链路与流程图 | `change-<feature>.svg` | 上半部分：链路节点（现有 / 修改 / 新增三种颜色）；下半部分：改造后的时序；有表结构变更时再加一块 |
| 白嫖区 / 开发区边界图 | `boundary.svg` | 二次开发模式 |
| 运行链路图 | `run-chain.svg` | 二次开发模式 |

文档里一律用图片链接引用（写法是感叹号、方括号里的图名、圆括号里的相对路径，例如 `diagrams/architecture.svg`），不内嵌 Mermaid 或其他画图代码。

内容多的图（架构图、模块依赖图、改造链路与流程图）宁可把画布加高，也不拆成多张。

## 2. 怎么画

**默认直接手写 SVG**，从 `templates/diagram-base.svg` 复制一份开始。底稿里已经有画布、背景、标题、箭头标记、阴影、常用样式类和图例。

本机已经装好 claude-mermaid 或 mermaid-cli（`mmdc`）时，可以先写 Mermaid 再渲染成 SVG。但最终交付的只能是 `.svg` 文件，并且同样要过第 5 节的自检。不要为了画图去全局安装任何软件。

## 3. 视觉规范

| 项 | 规定 |
| --- | --- |
| 字体 | `font-family="'PingFang SC','Noto Sans CJK SC','Microsoft YaHei',sans-serif"` |
| 背景 | `#FBF7F0` |
| 核心节点 | 填充 `#EAF1F8`，边框 `#1F4E79`，标题字 `#1F4E79` |
| 强调节点（入口、主干） | 填充 `#1F4E79`，白字 |
| 周边 / 基础设施 | 填充 `#F4EEE3`，边框 `#D9CBB5` |
| 外部依赖、产出 | 填充 `#FFF4E8`，边框 `#E8692E` |
| 需要人注意（循环依赖、风险、待确认） | 填充 `#FCD86B`，边框 `#C77700`；循环依赖的连线用 `#D64545` |
| 分组框 | 白底，边框 `#D9CBB5`，圆角 14，左上角写组名 |
| 节点 | 圆角 8–12；第一行写名字（14–17px，加粗），第二行写一句话职责（12.5–13.5px） |
| 连线 | 实线 = 调用 / 依赖；虚线 = 异步、逻辑关联或生成关系；必须带箭头 |
| 标题 | 左上角，26–30px 加粗，下面一行写副标题（图的范围和来源） |

## 4. 布局规则

1. **先算坐标，再动笔。** 先列出每一层有哪些节点，算好每个节点的 x、y、宽、高，再写 SVG。同一层的节点等宽、等间距。
2. **估算文字宽度，防止溢出。** 中文字符宽度约等于字号，英文和数字约 0.55 倍字号。节点宽度至少等于「最长一行文字的估算宽度 + 32」。放不下时，把字拆成两行，或者加宽节点，不要缩小字号硬塞进去。
3. **固定方向**：全项目统一从上到下（应用架构、技术架构、模块依赖）或从左到右（链路、流程）。时序图里参与者横向排开，消息自上而下。
4. **连线不穿节点**：需要绕行的用折线（path 里的 `L` / `H` / `V` 段）。连线上的标签放在线段中点，旁边留出空白。
5. **图是索引，不是百科。** 一张图最多放 20 个左右的节点（技术架构图把外部依赖算在内可以到 30 个）。放不下时先把周边能力合并成一个框，或者按层分组、加高画布。
6. **画布大小**：宽 1200–1600，高按内容来定。`viewBox` 和 `width`、`height` 保持一致。
7. **每张图右下角**用小字写出数据来源，比如「来源：pom.xml、application.yml，YYYY-MM-DD」。

## 5. 自检（每张图都做）

1. **结构合法**：

   ```bash
   python3 -c "import sys,xml.etree.ElementTree as E; r=E.parse(sys.argv[1]).getroot(); assert r.tag.endswith('svg'); print('ok')" <文件>.svg
   ```

2. **截图看一遍**（本机有 Chrome 或 Chromium 时必须做）。截图放在临时目录，不放进产出目录：

   ```bash
   google-chrome --headless=new --no-sandbox --hide-scrollbars --force-device-scale-factor=2 \
     --window-size=<宽>,<高> --screenshot=/tmp/<名>.png <文件>.svg
   ```

   然后打开截图逐项看：
   - [ ] 文字没有溢出节点，没有互相重叠
   - [ ] 连线没有穿过节点，箭头方向对
   - [ ] 中文正常显示（没有变成方块）
   - [ ] 颜色语义和第 3 节一致，图例齐全

   没有浏览器的，就逐个节点核对第 4 节第 2 条的宽度估算，并在总说明里注明「SVG 未经截图检查」。

3. **内容对**：每个节点、每条连线都能在代码或配置里找到依据，符合各阶段规格里的自检项。
